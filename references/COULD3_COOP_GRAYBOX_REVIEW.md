## 구현 범위

- 개발 레벨: `c3-coop-test`, 2560×768, 우향 진행
- 전용 장면: `CoopPrototypeScene`
- 진입 조건: `coopReview=1`과 `debug=1`이 모두 있을 때만 활성화
- P1: 실세아, 키보드 방향키/WASD + Space/Z
- P2: 89% 구운 감자, pad 0 스틱/D-pad + A
- 공용 재사용: `Player`, `LevelLoader`, 기존 캐릭터·배경·타일·아이템 에셋
- 신규 아트 없음. 정상 에셋과 코드 도형 fallback을 모두 사용한다.

이번 승인 화면은 C3.2 입력 경계와 C3.3 두 플레이어 생성·코스 배치만 검수한다. 개별 체력·변신, 공유 수집, 거리 경고·재합류, 적·보스, 동시 게이트는 다음 구현 단계이며 아직 동작 완료로 간주하지 않는다.

## 코스 구성

| 구간 | x 범위 | 회색상자 목적 |
|---|---:|---|
| `coop_start` | 0~704 | 두 플레이어 생성, 번호 표식과 입력 분리 |
| `coop_separation` | 704~1536 | 낮은·높은 발판과 변신 아이템 배치 |
| `coop_rally` | 1536~2112 | 재합류·공유 체크포인트 후속 구현 자리 |
| `coop_finish` | 2112~2560 | 두 플레이어 동시 게이트 후속 구현 자리 |

지면은 전 구간 연결해 입력 분리 검수 중 낭떠러지로 흐름이 끊기지 않게 했다. 플레이어 사이 물리 충돌은 등록하지 않았으며 각 플레이어는 지형과 독립적으로 충돌한다.

## 식별·안내

- P1은 파란 원형 `1`, P2는 분홍 마름모 `2`를 캐릭터 위와 상단 안내에 반복한다.
- 색상만 보지 않아도 숫자와 형태로 구분할 수 있다.
- P2 게임패드가 없으면 `게임패드 연결 대기`를 표시하고 P1 장면은 유지한다.
- 하단에 `C3 개발 전용 · 진행과 해금은 저장하지 않음`을 항상 표시한다.
- 디버그 snapshot의 `savedProgress`는 항상 `false`이며 플레이어 ID·캐릭터·연결·좌표·활성 상태만 노출한다.

## 검수 주소

- 정상 초기 배치: `http://127.0.0.1:5173/?coopReview=1&debug=1`
- 분리 배치 fallback: `http://127.0.0.1:5173/?coopReview=1&coopState=spread&debug=1&fallback=1&mute=1`
- 격리 확인: `http://127.0.0.1:5173/?coopReview=1&mute=1`

`coopState=spread`는 P1 x=480, P2 x=1120에 놓아 640px 간격에서도 두 표식과 코스가 함께 판독되는지 보는 고정 상태다. 격리 확인 주소는 `debug=1`이 없으므로 일반 메뉴로 진입해야 한다.

## 확인 결과

- 정상 1280×720: P1 x=176, P2 x=272, 두 body 활성, P2 미연결 대기
- fallback 1280×720: P1 x=480, P2 x=1120, 코드 도형 캐릭터와 번호 표식 판독
- 두 플레이어의 캐릭터 ID가 각각 `silsea`, `potato89`로 고정됨
- 미연결 pad의 선택적 버튼 값이 `NaN` 속도를 만들던 문제를 `Boolean` 정규화로 수정
- `debug=1` 없는 주소에서 협동 snapshot이 생성되지 않고 일반 메뉴로 진입
- 브라우저 warning/error 0건
- `npm run test`, `npm run validate`, `npm run build`, `git diff --check` 통과 대상
