# 실세아

실세아와 89% 구운 감자 중 한 캐릭터를 골라 달리고 점프하며, 유니콘·페가수스·알리콘으로 변신해 감자 대왕을 물리치는 브라우저용 2D 횡스크롤 액션 게임입니다.

현재 Phase 4 Polish와 스테이지 확장 P8까지 구현·승인되어 있습니다. 다섯 개의 데이터 기반 레벨, 키보드·게임패드 조작, 쉬운 모드, 음량·음소거, 화면 흔들림 설정, 로컬 진행도 저장, 로컬 이미지·오디오 에셋과 무음/도형 fallback을 포함합니다. P8 자동 검증과 `child-01` 일반·키보드 4개 레벨 테스트를 통과했으며, 잔여 2명 테스트는 사용자 최종 승인에서 미실시 예외로 남겼습니다.

## 실행 환경

- Node.js 20.19+ 또는 22.12+ 권장
- npm 10 이상 권장
- WebGL 또는 Canvas를 지원하는 최신 데스크톱 브라우저

현재 릴리스 검증 환경은 Node.js 24.13.0, npm 11.6.2입니다.

```bash
npm install
npm run dev
```

개발 서버가 출력한 로컬 주소를 브라우저에서 엽니다. 기준 해상도는 1280×720이며, 다른 화면 크기에서는 16:9 비율을 유지한 채 맞춰집니다.

프로덕션 결과를 확인하려면 다음 명령을 사용합니다.

```bash
npm run build
npm run preview
```

`npm run build` 결과는 `dist/`에 생성됩니다. 런타임 이미지와 오디오는 모두 저장소 내부 상대 경로를 사용하므로 배포 결과가 외부 에셋 서버에 의존하지 않습니다.

## 조작

| 행동 | 키보드 | 게임패드 |
|---|---|---|
| 이동·메뉴 선택 | 방향키 / WASD | D-pad / 왼쪽 스틱 |
| 점프·비행·확인 | Space / Z / Enter | A |
| 날개로 투사체 방어 | Shift / X | X |
| 일시정지 | Esc | Menu / Start |
| 화면 흔들림 전환 | V | 일시정지 메뉴에서 변경 |
| 전체 음소거 전환 | M | 일시정지 메뉴에서 변경 |

일시정지 메뉴에서는 BGM·효과음 볼륨, 전체 음소거, 화면 흔들림, 조작 안내와 쉬운 모드를 변경할 수 있습니다. 쉬운 모드 변경은 현재 스테이지를 새 설정으로 다시 시작합니다.

## 게임 구성

- `실세아`와 `89% 구운 감자`는 외형과 애니메이션이 다르지만 이동·변신 성능은 같습니다.
- 유니콘은 주변 별을 끌어오고 가시 호박을 파괴합니다.
- 페가수스는 최대 10초 동안 날며, 지상에서 비행 게이지를 회복합니다.
- 알리콘은 12초 동안 무제한 비행, 넓은 자석, 무적과 점수 배율을 제공합니다.
- HP가 소진되거나 낭떠러지에 빠지면 마지막 체크포인트에서 빠르게 재개합니다.
- 감자 대왕의 세 단계 약점을 공략한 뒤 무지개 게이트에 도달하면 스테이지를 완료합니다.
- 최고 점수와 달성 목표는 브라우저 `localStorage`의 `silsea:progress:v1`에 저장됩니다. 저장소 사용이 차단되면 현재 탭의 메모리 상태로 계속 플레이합니다.

더 자세한 규칙은 [GAME_DESIGN.md](./GAME_DESIGN.md), 레벨 데이터 규격은 [LEVEL_SCHEMA.md](./LEVEL_SCHEMA.md), 현재 진행 상태는 [ROADMAP.md](./ROADMAP.md)를 참고합니다.

## 플레이테스트 기록

대상 어린이 플레이테스트는 익명 테스트 ID를 쿼리에 지정해 시작합니다. 이름이나 연락처 같은 개인 정보는 입력하지 않습니다.

```text
http://localhost:5173/?playtest=1&tester=child-01&level=level-02
http://localhost:5173/?playtest=1&tester=child-02&level=level-04&shake=0
http://localhost:5173/?playtest=1&tester=child-03&level=level-05&easy=1&effects=reduced
```

플레이 중 구간별 체류시간, 피격, HP 손실, 추락, 체크포인트와 부활 좌표, 쓰나미 피격, 숨 0 도달, 투사체 방어, 보스 타격과 20초 이상 진행하지 못한 위치가 자동 기록됩니다. 클리어 화면에서 `E` 또는 결과 저장 버튼을 누르면 현재 브라우저에 저장된 최근 24개 세션과 분석 결과를 JSON으로 내려받습니다.

분석 결과는 서로 다른 테스트 ID 3명의 완주 기록이 모였는지, 두 명 이상이 같은 구간에서 피격·추락·정체했는지, 일반 모드 6~9분과 쉬운 모드 5~8분 범위를 충족했는지, 모드별 평균 HP 손실이 얼마인지를 표시합니다. 다른 장치에서 받은 JSON은 `npm run playtest:analyze -- <파일...>`로 합쳐 분석할 수 있습니다. 기록은 브라우저 `localStorage`의 `silsea:playtests:v2`에만 저장되며 외부로 전송되지 않습니다. 기존 v1 기록은 읽을 때 자동 변환합니다. 전체 절차는 [P8 플레이테스트 가이드](./references/P8_PLAYTEST_GUIDE.md)를 따릅니다.

현재 확장 P1의 공용 환경 기술은 개발 전용 시험 코스에서 확인할 수 있습니다. 이 코스는 스테이지 선택과 저장 진행도에는 나타나지 않습니다.

```text
http://localhost:5173/?p1test=1
http://localhost:5173/?p1test=1&easy=1
http://localhost:5173/?p1test=1&fallback=1&effects=reduced
http://localhost:5173/?p1test=1&debug=1
```

오른쪽에서 왼쪽으로 진행하면서 쓰나미 경고·대피처·파도 통과, 단일 물 영역의 잠수·숨 회복·숨 0 이후 HP 피해를 확인합니다.

## 검증

변경 종류에 맞는 명령만 실행할 수 있지만, 릴리스 전에는 아래 다섯 명령을 모두 통과시키는 것을 기준으로 합니다.

| 명령 | 확인 범위 |
|---|---|
| `npm run spritesheets` | 승인 프레임에서 캐릭터·유니콘·수영 시트를 재조립하고 산출물 드리프트 확인 |
| `npm run test` | 이동 수학, 점수, 변신, 난이도, 오디오, 카메라 효과 등 코어 회귀 테스트 |
| `npm run validate` | 레벨·구조·manifest·이미지 규격·팔레트·에셋 정합성 검사 |
| `npm run test:soak` | 60분 등가 프레임, Scene 재시작과 Object Pool·파티클 상한 검사 |
| `npm run test:release` | 프로덕션 빌드와 배포 결과의 로컬 런타임 에셋 검사 |

`npm run validate:assets`는 검증 결과와 함께 `references/asset-report.html`을 갱신합니다. 사람이 확인해야 하는 항목과 남은 플레이테스트는 [TEST_CHECKLIST.md](./TEST_CHECKLIST.md)에 기록합니다.

## 프로젝트 구조

| 경로 | 역할 |
|---|---|
| `src/scenes/` | 부트, 메뉴, 선택, 게임, HUD, 클리어 흐름 |
| `src/entities/` | 플레이어 런타임 엔티티 |
| `src/systems/` | 입력, 레벨, 적, 보스, 변신, 체력, 점수, 오디오 등 독립 시스템 |
| `src/data/` | 캐릭터·적·게임플레이·애니메이션과 레벨 데이터 |
| `assets/manifest.json` | 런타임 에셋 키, 파일 경로, 스프라이트 시트 규격의 단일 등록 지점 |
| `assets/` | 캐릭터, 적, 아이템, 배경, 타일, 레벨, 오디오 런타임 파일 |
| `scripts/` | 시트 조립, 생성, 자동 테스트와 검증 도구 |
| `references/` | 승인 기준, 매핑, 런타임·에셋 검수 보고서 |

새 레벨은 `src/data/levels/`에 데이터 파일을 추가하고 `src/data/levels/index.js`에 등록합니다. `GameScene`이나 시스템에 레벨별 좌표를 직접 추가하지 않습니다.

## 에셋 교체

런타임 코드는 파일 경로보다 `assets/manifest.json`의 키를 참조합니다. 기존 에셋을 교체할 때는 가능한 한 키, 파일명, 크기와 프레임 수를 유지하면 코드 변경 없이 교체할 수 있습니다.

### 공통 절차

1. `ASSET_LIST.md`에서 대상의 크기·프레임·역할 규격을 확인합니다.
2. 기존 manifest 키를 유지해 해당 런타임 파일을 교체합니다. 경로나 규격이 달라지면 `assets/manifest.json`도 함께 수정합니다.
3. 새 키를 추가했다면 `references/mapping.json`에 소유 관계를 정확히 한 번 등록하고, 사용하는 레벨 또는 애니메이션 데이터에 연결합니다.
4. `npm run validate`로 파일 존재, 키 중복, 크기, 알파, 팔레트, 기준선과 매핑 정합성을 검사합니다.
5. `npm run test:release`로 빌드 결과에 외부 URL이나 빠진 런타임 파일이 없는지 확인합니다.
6. `references/asset-report.html`과 실제 게임 화면을 모두 확인합니다.

### 종류별 주의사항

- 캐릭터와 적 프레임은 투명 PNG 128×128, 오른쪽을 보는 방향, 공통 발 기준선을 사용합니다. 원본 프레임은 `assets/characters/<캐릭터>/<동작>/` 또는 `assets/enemies/<적>/<동작>/`에 두고 `npm run spritesheets`로 시트를 다시 조립합니다.
- 생성된 시트만 직접 고치면 다음 조립 때 덮어써집니다. 재생성할 에셋은 개별 원본 프레임도 함께 교체합니다.
- 프레임 수를 바꿀 때는 manifest의 `frames`와 `src/data/characterAnimations.js` 또는 `src/data/enemyAnimations.js`의 duration 배열 길이를 함께 맞춥니다.
- 아이템은 `assets/items/`, 배경은 `assets/backgrounds/`, 타일은 `assets/tiles/`의 파일과 manifest 항목을 함께 관리합니다. 배경은 2048/3072px 폭, 720px 이상 높이와 좌우 seamless 조건을 유지합니다.
- SFX와 BGM은 `assets/audio/sfx/`, `assets/audio/bgm/`의 WAV 파일입니다. 기존 키를 유지하면 호출 코드를 바꿀 필요가 없고, 새 키는 manifest와 `AudioManager`를 사용하는 이벤트 경로에 연결해야 합니다.
- 로드에 실패한 이미지는 이름이 적힌 도형으로, 오디오는 무음으로 대체됩니다. fallback은 개발 안전망이며 정상 릴리스에서 누락 에셋을 허용하는 기준은 아닙니다.

전체 fallback 흐름은 원본 에셋을 옮기지 않고 아래 주소로 검증할 수 있습니다. `fallback=1`은 manifest 이미지·오디오 로드를 의도적으로 생략하지만 레벨 데이터와 타일맵은 유지합니다.

```text
http://localhost:5173/?fallback=1
```

## 알려진 제한

- 원래 계획한 어린이 3명의 무설명 플레이테스트 중 `child-01`만 수행했습니다. `child-02` 게임패드·흔들림 Off와 `child-03` 쉬움·효과 약하게·음소거 테스트는 사용자 최종 승인에서 미실시 예외로 수용했으므로 3인 공통 정체 여부는 확인되지 않았습니다.
- 작성된 플레이 스테이지는 `level-01`~`level-05` 다섯 개이며, `p1-environment-test`는 개발 전용 코스입니다.
- 게임플레이 입력은 키보드와 단일 게임패드만 지원합니다. 메뉴의 포인터 입력은 지원하지만 모바일용 화면 터치 이동·점프 버튼은 없습니다.
- 진행도는 현재 브라우저의 로컬 저장소에만 남습니다. 계정, 클라우드 동기화, 기기 간 이전 기능은 없습니다.
- 온라인 기능, 경쟁 랭킹과 동시 2P는 현재 범위에 포함되지 않습니다.
- Shift/X 및 게임패드 X는 입력 예약만 되어 있고 연결된 특수 행동이 아직 정의되지 않았습니다. 실제 게임의 조작 안내에는 동작하는 이동·점프·비행만 표시합니다.
- 일반 노트북 60FPS와 일부 수동 조작·접근성 항목은 실제 대상 기기에서 [TEST_CHECKLIST.md](./TEST_CHECKLIST.md)에 따라 최종 확인해야 합니다.

## 2P 확장 기록

현재 구현은 `GameScene.player`, 플레이어 한 명에 연결된 체력·변신 관리자, 그리고 `InputManager`의 키보드 및 첫 번째 게임패드(`getPad(0)`)를 전제로 합니다. 2P는 이 단일 소유권을 명시적으로 분리한 뒤 추가해야 하며, `GameScene`을 복제해 별도 2P Scene을 만드는 방식은 사용하지 않습니다.

권장하는 첫 확장 범위는 한 화면 로컬 협동입니다.

- 개인 상태: 입력, `Player`, HP, 무적 시간, 변신 형태, 비행 게이지, 애니메이션.
- 공유 상태: 레벨, 체크포인트, 목표, 보스 HP, 게이트, 팀 점수와 진행도.
- 카메라: 두 플레이어를 포함하는 공통 bounds와 제한된 줌을 먼저 적용합니다. 분할 화면은 후속 범위로 둡니다.
- 실패 처리: 한 명이 쓰러지면 활성 플레이어 또는 공유 체크포인트 근처에서 복귀시키고, 두 명이 동시에 진행 불능일 때만 체크포인트 전체 재시작을 고려합니다.

구현 순서는 다음과 같습니다.

1. `InputManager`가 `keyboardProfile`, `padIndex`를 받도록 바꾸고 플레이어별 입력 스냅샷을 독립 생성합니다. 현재 `getPad(0)` 하드코딩과 키 상태 공유를 제거합니다.
2. `GameScene`의 `this.player`를 플레이어 컨텍스트 배열로 바꿉니다. 각 컨텍스트는 `player`, `healthManager`, `transformationManager`, 입력과 개인 파티클/오디오 루프 소유권을 가집니다.
3. 지형 collider는 플레이어별로 만들고, 아이템·적·보스 overlap에는 `playerId`를 전달합니다. 같은 프레임에 두 플레이어가 아이템을 중복 획득하지 않도록 소비 상태를 먼저 잠급니다.
4. `ScoreManager`, `ObjectiveManager`, `CheckpointManager`, `BossController`는 팀 공유 객체로 유지하되 점수 이벤트에 기여 플레이어 ID를 선택적으로 기록합니다.
5. `UIScene`을 플레이어별 HP·형태·게이지와 공유 점수·목표 영역으로 나눕니다. 색상만으로 1P/2P를 구분하지 않고 초상화와 위치를 함께 사용합니다.
6. 캐릭터 선택 화면에 참가/이탈과 중복 입력 방지를 추가하고, `ProgressManager`는 기존 `v1` 기록을 읽을 수 있는 `v2` 마이그레이션을 거쳐 협동 최고 점수를 저장합니다.
7. 서로 다른 게임패드 입력, 동시 아이템 충돌, 한 명의 낭떠러지·부활, 카메라 이탈, 보스 막타, Scene 재시작 뒤 listener 정리를 자동·수동 테스트에 추가합니다.

이 경계를 먼저 지키면 기존 레벨 파일과 적·보스 데이터는 그대로 재사용할 수 있습니다. 온라인 멀티플레이는 입력 지연, 권한 모델과 상태 동기화가 별도로 필요하므로 로컬 2P와 같은 작업으로 취급하지 않습니다.
