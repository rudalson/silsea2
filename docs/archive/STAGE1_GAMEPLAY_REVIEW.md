## 결론

현재 문제는 적과 아이템의 수보다 **플레이어가 실제로 지나가는 길과 게임 요소가 놓인 길이 어긋나는 것**이다. 먼저 접근 불가능한 배치와 필수 능력 누락을 고치고, 이후 능력 획득 → 안전한 연습 → 응용 → 보상이 이어지도록 재구성하는 것을 권장한다.

우선순위는 다음과 같다.

1. 과수원 발판 아래 가시 호박을 삭제하고 감자 순찰을 접근 가능한 영역으로 제한한다.
2. 뿔·날개를 주 동선에서 확실히 획득하게 하고, 발판 내부 별을 재배치한다.
3. 날개 획득 후에도 기존 수집 능력이 유지되도록 성장 규칙을 정리한다.
4. 비행·이동 발판·상승기류·붕괴 발판의 역할을 분리한다.
5. 알리콘 구간의 보상을 강화하고, 안전한 회복과 보스 준비를 보장한다.

아래 1~7절은 2026-09-21 수정 전 검토와 제안이다. 사용자 요청에 따라 게임 로직과 배치를 수정했으며, 현재 적용 결과는 **8절 개선 적용 기록**에 별도로 정리했다.

## 검토 근거와 한계

- 레벨 데이터, 타일맵의 전체 충돌 지형, 적·장애물 판정, 수집·변신·비행·체크포인트·보스 규칙을 대조했다.
- 브라우저에서 과수원, 알리콘 구간, 회복길의 실제 화면을 확인했다. 과수원에서 첨부 이미지와 같은 배치를 재현했다.
- 별 아치를 실제 생성 공식으로 전개해 122개의 별 좌표와 지형 겹침을 검사했다.
- `node scripts/validate-levels.js` 통과. 현재 검증은 아래의 동선·성장 설계 문제까지 검출하지 않는다.
- 모든 구간을 처음부터 끝까지 조작해 완주한 검토는 아니다. 도달성 판단은 충돌 크기·지형·능력 규칙을 이용한 분석이며, 제안 좌표와 체감 난이도는 후속 플레이테스트가 필요하다.
- 화면 확인용 `visualReview`는 위치·변신을 지정하고 알리콘 시간을 무제한으로 만들 수 있으므로, 화면 확인 결과를 정상 플레이의 획득 성공이나 12초 타이밍 검증으로 취급하지 않았다.
- 기존 기획 문서는 의도 비교 자료로만 참고했다. 문서에 적힌 과거 규칙을 현재 요구사항이나 변경 승인으로 간주하지 않았다.

## 1. 첨부 이미지의 문제

말씀하신 뿔난 감자는 코드상 `spike_pumpkin`인 가시 호박이다. 옆의 갈색 감자는 순찰하는 `raw_potato`다.

| 요소 | 현재 배치 | 실제 의미 | 권장 수정 |
|---|---|---|---|
| `pumpkin_orchard_02` | (6080,576), `orchard_step_3` 아래 | 발판 x=5952~6144, y=496~544. 바닥 y=576과의 틈은 32px인데 캐릭터 몸은 58px. 호박 판정도 발판 안쪽에 있어 위·옆의 정상 동선에서 닿을 수 없다. 접촉 외 공격도 없다. | **삭제 우선.** 같은 좁은 발판 위로 옮기면 착지 공간을 차지하므로, 적이 필요하다면 별도의 넓은 착지대에 배치한다. |
| `e_orchard_potato_02` | 중심 x=6208, 순찰 범위 6032~6384 | 감자의 아트 적용 몸 높이는 약 26px라 32px 틈에 들어갈 수 있다. 플레이어는 못 들어간다. 틈 밖에서는 상호작용 가능하므로 완전히 무의미한 적은 아니지만, 숨는 동안 대응할 수 없다. | 순찰을 열린 바닥이나 발판 위로 제한한다. 외형상 좁은 틈에 숨도록 만드는 현재 순찰 범위를 제거한다. |

이 문제를 고치려고 전체 발판을 일괄적으로 아래에서 통과 가능한 발판으로 바꾸는 것은 권장하지 않는다. 기존 점프·천장·위험물 관계가 모두 바뀐다. 해당 배치와 낮은 틈부터 정리하는 편이 범위가 명확하다.

## 2. 현재 성장 구조

| 획득물 | 현재 실제 효과 | 성장 관점의 판단 |
|---|---|---|
| 별 122개 | 기본 10점, 콤보, 별 70개 선택 목표 | 탐색·수집 보상. 체력·공격력·이동 능력은 증가하지 않는다. |
| 작은 퍼센트 4개 | 기본 25점 | 점수 보상이며 회복 아이템이 아니다. |

| 뿔 1개 | 유니콘 변신, 별 자석 반경 176px | 수집이 편해지는 첫 변화는 있다. 실제 가시 호박 파괴에는 연결되지 않는다. |
| 날개 1개 | 페가수스로 교체, 비행 게이지 10초, 지상 약 3초로 완충, 날개 방어 | 이동 능력이 늘지만 유니콘 자석은 사라진다. 누적 강화보다 능력 교체다. |
| 알리콘 1개 | 12초 무적·무제한 비행·자석 292px·적 접촉 처치·획득 점수 2배 | 명확한 강화지만 일시적이며, 끝나면 이전 형태로 돌아간다. 가시 호박은 사라지지 않는다. |

`canBreakObstacles`는 정의되어 있지만 가시 호박 접촉 처리에서 사용하지 않는다. 현재는 유니콘도 가시 호박에 피해를 받고, 알리콘은 무적으로 피해를 무시할 뿐 파괴하지 않는다. 과거 기획의 ‘뿔로 호박 파괴’와 현재 구현이 다르다.

**권장 성장 방향:** 기본 이동 → 뿔로 수집 능력 획득 → 날개로 수집 능력을 유지하며 비행 추가 → 알리콘으로 잠시 능력 증폭.

- 날개를 먹어도 획득한 자석 능력이 유지되게 한다. 영구 알리콘을 주는 대신 ‘해금한 능력’과 ‘피버 상태’를 구분한다.
- 뿔에 전투·지형 역할이 필요하다면 균열 상자 같은 별도의 파괴 가능한 물체를 안전한 곳에 소개한다. 기존 가시 호박을 갑자기 안전한 대상으로 바꾸는 것보다 위험물 규칙을 일관되게 유지하기 쉽다.
- 별은 우선 길 안내와 선택 보상 역할을 유지한다. 단순히 수치 성장 재화를 추가하기보다, 능력을 얻은 직후 이전에 못 하던 행동에 성공하도록 배치하는 것이 먼저다.
- 수집에 따른 추가 성장이 필요하면 일정 별 수에서 작은 보너스를 주는 2차 개선으로 검토한다. 필수 비행 능력을 별 개수에 묶어 진행을 막지는 않는다.

## 4. 아이템별 처리 의견

아이템 y는 통일된 의미가 아니다. 별은 중심 좌표를 그대로 쓰고, 뿔·날개·알리콘·퍼센트는 데이터 y에서 44px 위에 실제 중심이 생긴다.

### 필수 능력 3개

- `horn_intro` (1792,496), `wings_intro` (6912,496), `alicorn_intro` (11648,496): 실제 수집 중심 y=452, 판정 y=428~476. 지상 캐릭터 판정은 대략 y=518~576이므로 그냥 달리면 겹치지 않는다. 약 42px 이상 올라가야 판정이 닿기 시작한다.
- 뿔·날개는 본선에서 자연스럽게 획득하도록 바닥 기준 데이터 y=576 부근으로 내리는 안이 단순하다. 이때 실제 중심 y=532가 되어 지상 캐릭터와 충분히 겹친다. 또는 능력을 얻어야 통과하는 짧고 안전한 획득 구간을 설계한다.
- 이미 비행하는 상태로 만나는 알리콘은 지상 배치만으로 획득을 보장하지 못한다. 앞에서 안전하게 착지하도록 길을 합류시키고 체크포인트 다음에 놓는다. 현재 CP4와 같은 x=11648이므로, 체크포인트 → 아이템 → 체험 대상의 순서가 보이도록 간격을 둔다.
- 빠뜨린 능력을 뒤쪽에서 보충할 방법을 마련한다. 다만 비행 없이도 구덩이의 발판·상승기류를 이용할 가능성이 있으므로 현재 상태를 곧바로 ‘진행 불가’라고 단정하지 않는다.

## 6. 체크포인트·회복·보스

- 일반 난이도 체크포인트는 x=4480, 7296, 9792, 10560, 11648, 14176의 6개다. 쉬운 모드에는 x=8832가 추가된다.
- 현재 일반 CP는 비행 에너지를 회복하고, HP 완전 회복은 CP5만 한다. 퍼센트 아이템이나 다른 CP를 HP 회복 수단으로 계산하면 안 된다.
- CP의 판정은 폭 64px, 높이 112px인 지상 영역이므로 위로 지나가면 활성화되지 않는다. 특히 CP1은 상단 보상 길 아래이고, CP5도 하늘 정원에서 날아서 넘어갈 수 있다.
- 첫 CP까지 4,352px를 진행해야 하므로 첫 변신을 막 배운 초보자에게 재시도 거리가 길다. 뿔 체험 뒤 첫 본격 장애물 전에 안전 지점 하나를 추가하는 안을 권장한다.
- CP1·CP5는 상·하단 경로 합류점에 둔다. 핵심 CP를 높게 날아 지나가도 저장되게 할 경우에는 먼저 안전한 복귀 위치를 보장하고, 화면에서 저장을 인지하게 해야 한다.
- 긴 구덩이 직후 CP와 낙뢰 공격 트리거가 x=10560으로 같다. 현재 지연·예고 덕분에 즉시 맞는 배치는 아니지만, ‘휴식 지점’과 ‘전투 시작’은 조금 분리하는 편이 좋다.
- 알리콘 획득 x=11648에서 축제 끝까지는 최고 수평 속도 360px/s 기준 약 4.6초, 보스 입구까지는 약 7.5초다. 장애물·가속·정지 시간을 제외한 거리 환산값이므로 실제 소요 시간은 더 길다. 그래도 12초 피버가 축제 구간에만 머무르도록 설계된 상태는 아니다.
- 보스까지 피버를 가져가는 것을 보상으로 허용할지, 축제 안에서 소진시키도록 코스를 늘릴지 결정해야 한다. 초보 학습을 중시한다면 축제 보상을 늘리고 회복 구간에서 피버 종료를 자연스럽게 경험하게 하는 쪽을 권장한다. 입장 시 설명 없이 강제로 능력을 뺏는 방식은 피한다.
- 알리콘은 공중에서 종료되면 가까운 정적 지형으로 위치가 보정된다. 안전망은 유용하지만 갑자기 위치가 바뀌는 경험이 되므로 종료 예고와 넓은 착지 공간을 함께 둔다.
- 날개 방어는 현재 스테이지 1의 구름·까치·감자 대왕 탄환을 막는 핵심 대응으로 연결되어 있지 않다. 이를 가르칠 필요가 없다면 스테이지 1에서는 비행만 소개하고, 실제로 방어할 수 있는 투사체가 나오는 스테이지에서 방어를 가르친다.

## 7. 권장 수정 단계와 검증 기준

### 1차: 배치 정리

- 접근 불가능한 `pumpkin_orchard_02` 제거.
- 과수원 감자 2개와 알리콘 감자의 순찰·시작 위치 조정.
- 필수 변신 아이템의 획득 동선 정리.
- `recovery_arc`의 발판 관통 및 과수원 바닥 별의 시각적 겹침 제거.
- CP1·CP5의 경로 합류와 회복 안내 보완.

검증: 세 캐릭터의 기본 형태·유니콘·페가수스에서 확인한다. 달리기만 하는 경로, 상단 보상 경로, 능력을 일부러 놓치는 경로, 사망 후 재시도를 따로 점검한다. 적은 전체 순찰 주기 동안 플레이어가 접근 가능한 영역에 남아야 한다.

### 2차: 성장과 학습 구조

- 뿔 → 날개의 능력 유지 규칙 적용.
- 안전 비행·충전 연습과 첫 공중 공격을 분리.
- 이동·붕괴 발판은 명확한 선택 보상을 부여하거나 뒤 스테이지로 이동.
- 알리콘 구간에 기존 반복 적·별을 재배분해 강화 체감을 높임.

검증: 능력을 처음 얻은 사용자가 다음 1~2개 화면에서 효과를 이해하고 성공하는지 관찰한다. 비행을 쓰지 않는 경로는 필수 완주 경로인지 선택 도전인지 먼저 결정하고 검증한다.

### 3차: 실제 플레이로 보상 밀도 조정

- 별 70개 목표는 현재 122개의 약 57%다. 총량만으로 쉽거나 어렵다고 단정할 수 없다. 보통 본선으로도 목표에 근접하고, 일부 선택 경로가 목표 달성을 도와주는지 확인한다.
- 실제로 이용되지 않는 발판, 항상 건너뛰는 보상, 설명 없이 피격되는 위험물의 수를 기록한다.
- 피버를 얻는 시점·종료 위치·보스 진입 시 잔여 시간, CP 누락, 재시도 거리, 비행 게이지 최저치를 측정한다.
- 접근 불가능한 적·아이템이 0개이고 모든 선택 길이 보상 또는 지름길을 제공하는 상태를 완료 기준으로 삼는다.

현재 일반 모드 구성은 일반 적 10마리(생감자 6·공중 적 4), 가시 호박 3개, 구덩이 2개, 상승기류 2개, 주요 체크포인트 8개다. 쉬운 모드는 기존대로 공중 적 2마리를 줄이고 추가 체크포인트 1개를 제공한다.

### 설계 선택과 적용 범위

- 성장은 이번 스테이지 안의 **능력 누적과 보상 밀도**로 표현한다. 레벨업 수치·성장 재화·새 상자를 추가하는 안은 채택하지 않았다.
- 알리콘 12초는 유지한다. 축제에 감자 3마리와 별 29개를 배치하고, 빠른 플레이로 남은 피버를 보스까지 가져가는 보상은 허용한다. 보스 입장에서 강제로 해제하지 않는다.
- 무비행 완주는 필수 학습 목표로 잡지 않는다. 필수 날개를 놓치지 않게 하고, 에너지 소진에 대비한 착지·고정 발판 경로를 제공한다.
- 유니콘과 알리콘이 가시 호박을 파괴한다는 기존 설명은 실제 코드와 달라 수정했다. 가시 호박은 점프 회피 대상이고, 알리콘은 무적으로 통과한다.
- 다른 스테이지의 변신 교체 규칙과 보스 패턴은 유지한다. 공통 체크포인트 관리에는 진행 방향에 따른 저장 후퇴 방지를 적용했다.

### 검증 방법과 한계

- `npm test`: 기존 회귀 검사와 스테이지 1 추가 검사 통과. 세 캐릭터·양 난이도 배치, 공중/지상 필수 획득 판정, 피버 종료 후 능력 유지, 데이터 다시 읽기 복원, 정방향/역방향 체크포인트 복귀를 검사한다.
- `npm run validate`: 레벨·에셋 검사 통과. 스테이지 1의 아이템-지형 겹침, 접근 불가능한 생감자 순찰, 가시 호박 점프 공간, 안전하지 않은 복귀 지점은 이후 배치 수정에서도 오류로 검출한다.
- `npm run build`, `npm run validate:runtime`: 프로덕션 빌드와 로컬 런타임 에셋 검사 통과. Phaser 번들 크기 경고는 남아 있다.
- 개발용 `scripts/stage1-runtime.html`은 공중 변신 획득·체력 회복·실제 복귀를 확인한 뒤 레벨을 새로 시작한다. 이후 실제 입력과 Phaser 물리로 시작점부터 x=14300까지 주행한다. 본선에서는 순간이동이나 수집 함수 직접 호출을 사용하지 않는다.
- 배치 검사는 보수적인 충돌·공간 검사이며 모든 가능한 경로의 도달성을 증명하지는 않는다. 보스 처치·모든 선택 보상 획득·처음 플레이하는 사람의 학습 속도와 체감 난이도는 별도 플레이테스트 대상이다. 자동 주행 시간을 기존 목표 플레이 시간과 동일하게 해석하지 않는다.
