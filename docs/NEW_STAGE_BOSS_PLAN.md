# 신규 스테이지 5개·대왕 5종 개발 계획

작성일: 2026-10-22 · 상태: N1 장치 시험과 N2 메롱 왕국 구현·검증 완료, 다음 단계 N3 테이프 도시

N1 결과와 실제 검증 범위는 [신규 코스 장치 검수 기록](./NEW_COURSE_N1_REVIEW.md)에 정리했다. 피아노는 추천안인 자발적 5초 정지로 시험했으며, 영상 음성 전사는 여전히 미확인이다.

N2 결과는 [메롱 왕국 검수 기록](./MERONG_N2_REVIEW.md)에 정리했다. 7번을 실제 캠페인에 등록하고 6→7 해금, 혀 장치, 궁전 등장, 세 단계 머리 밟기와 게이트·저장을 연결했다. 8번은 N3에서 추가하므로 현재 7번 다음 스테이지는 없다. 아래 제안 중 N2의 최종 수치와 검증 범위는 해당 검수 기록을 따른다.

## 2. 현재 코드에서 재사용할 기반

- 계획 착수 시 플레이 가능한 레벨은 `level-01`~`level-06`이었다. 기존 1~5에는 보스가 있고, 6은 보스 없는 무지개 이어달리기다. N2에서 `level-07` 메롱 왕국을 추가했다.
- 레벨은 `src/data/levels/index.js`의 레지스트리에 등록한다. 신규 파일은 schema version 2를 사용한다.
- 보스 공통 진입점은 `BossController`이며 정의·패턴·행동이 분리되어 있다. 새 보스 Scene을 만들 필요가 없다.
- 기존 약점 공략은 위에서 내려오며 머리를 밟는 방식이다. 기본 HP 3과 타격 후 다음 패턴으로 넘어가는 구조를 재사용한다.
- 이동 발판·상승기류·붕괴 발판, 추락 복귀, 체크포인트, 쉬운 모드, 무지개 게이트, 로컬 진행 저장을 활용할 수 있다.
- 해금은 직전 순서의 레벨 클리어를 기준으로 한다. 기존 저장 ID를 유지하고 새 레벨 ID를 덧붙이면 기존 기록을 이어갈 수 있다.
- 스테이지 선택은 레벨 배열을 읽는 캐러셀이므로 11개 레벨 연결이 가능하다. 새 미리보기와 긴 이름·선택 점 표시를 실제 화면에서 확인한다.
- **N2에서 수정한 기존 가정:** 구조·게이트 검사의 고정된 6개 레벨 전제를 레지스트리 기반 검사로 바꿨다. 6→7 연결과 현재 마지막 레벨의 다음 레벨 없음도 검사한다.

현재 구간 판정은 x축 범위를 사용한다. 종이에 그린 세로·U자 배치를 그대로 복제하기보다는, **1차 구현은 횡스크롤 지형과 구간 연결로 재해석**하는 안을 제안한다. 실제로 되돌아오는 U자 경로나 방 사이 이동이 필요하면 별도의 진행·카메라 설계가 필요하다.

## 3. 스테이지 구성안

아래 순서·이름·패턴은 구름 코스 추가를 제외하면 개발 제안이다. 기존 1~6의 순서와 보스 구성은 유지한다.

| 순서 / ID | 스테이지 | 전용 보스 / 키 | 코스에서 배우는 행동 |
|---|---|---|---|
| 7 / `level-07` | 메롱 왕국 | 메롱 대왕 / `merong_king` | 혀가 나오는 예고를 보고 점프하거나 기다리기 |
| 8 / `level-08` | 테이프 도시 | 테이프 대왕 / `tape_king` | 끈끈한 바닥을 짧게 통과하고 안전 발판으로 이동하기 |
| 9 / `level-09` | 피아노 나라 | 음악 대왕 / `music_king` | 진행 신호에는 이동하고 정지 신호에는 5초 기다리기 |
| 10 / `level-10` | 구멍 코스 | 구멍 대왕 / `hole_king` | 구멍의 위치와 열릴 예고를 보고 착지점 고르기 |
| 11 / `level-11` | 구름 코스 | 구름 대왕 / `cloud_king` | 구름 발판·상승기류를 이용하고 돌풍 예고 피하기 |

모든 코스는 **안전한 소개 → 단독 연습 → 응용 구간 → 회복 체크포인트 → 보스 → 무지개 게이트**로 연결한다. 새 조작 버튼은 추가하지 않는 방향을 우선한다.

### 3.1 메롱 왕국

- 원안: 온통 메롱하는 왕국, 궁전 안에서 메롱 대왕 등장.
- 제안 코스: 입 모양 문과 혀 다리 → 혀가 뻗는 통로 → 높이가 다른 통로 → 궁전 입구.
- 혀 공격은 바닥 표시와 준비 동작으로 범위를 미리 보여준다. 장식용 혀와 피격 판정이 있는 혀는 외형으로 구별한다.
- 궁전 입구를 보스 구간의 진입 지점으로 사용해 원안의 등장 상황을 살린다.
- 보스 패턴 제안: ① 낮은 혀 한 번 ② 높낮이를 바꾼 두 번 ③ 예고 위치를 바꾼 연속 공격. 혀를 거둔 뒤 지친 상태에서 머리 약점을 연다.
- 1차로 이 스테이지 하나를 선택 화면부터 클리어까지 연결해 신규 확장의 기준 사례로 만든다.

### 3.2 테이프 도시

- 원안: 찐득찐득한 코스를 통과하며 테이프 대왕을 만난다.
- 제안 코스: 짧은 테이프 바닥 → 일반 바닥과 번갈아 있는 길 → 테이프 길·이동 발판 조합 → 작업장 보스방.
- 끈끈함은 우선 **지상 가로 이동 감속**으로 구현한다. 점프는 유지하고 완전히 갇히는 효과는 기본 규칙에 넣지 않는다.
- 제안 초기값: 지상 속도 0.6배, 쉬운 모드 0.8배. 실제 이동 감각을 확인한 뒤 조정한다.
- 테이프를 벗어나거나 부활·레벨 재시작·데이터 재로드를 하면 감속이 해제되어야 한다.
- 보스 패턴 제안: ① 테이프 조각 투척 ② 제한된 바닥에 끈끈이 설치 ③ 두 패턴을 순서대로 조합. 절단부에 테이프가 걸려 버둥거리는 동안 약점이 열린다.
- 한 화면의 안전한 착지점과 보스에게 접근하는 길은 항상 남긴다.

### 3.3 피아노 나라

- 원안: “띵!” 신호와 5초 정지, 건반 테마, 악기·음표를 든 음악 대왕.
- 추천 해석: 신호 뒤 플레이어가 **스스로 5초간 멈추는 규칙**. 소리와 함께 정지 아이콘·남은 시간을 표시하고 종료 신호를 준다.
- 제안 코스: 안전한 건반에서 신호 연습 → 이동과 정지 반복 → 건반 간 점프 → 음악 대왕 무대.
- 정지 구간은 안전한 착지 영역에서 시작한다. 공중에서 갑자기 멈추라는 판정을 내리지 않는다.
- 이동 판정에는 작은 허용 범위를 둬 게임패드 미세 입력이나 발판의 운반 이동 때문에 실패하지 않게 한다. 정지 시작 직전의 점프 입력이 종료 후 튀어나오지 않도록 입력 버퍼도 정리한다.
- 정지 시간 중에는 해당 구간의 공격·발판 붕괴를 함께 제어해 기다리는 동안 피할 수 없는 피해가 생기지 않게 한다. BGM·카운트다운과 일시정지 메뉴는 계속 동작한다.
- 실패 시에는 첫 연습에서 무해한 재안내, 본 구간에서 기존 HP 피해와 재도전 보호 시간을 적용하는 안을 제안한다.
- 보스 패턴 제안: ① 한 줄 음표 회피 ② 음표 공격 뒤 5초 정지 ③ 두 공격을 순서대로 조합. 정지 구간 성공 뒤 연주가 끝나는 순간 약점이 열린다.
- 강제 정지 효과가 원안이라면 이 항목을 교체한다. 안전 발판 위에서만 발동하고 위험 요소·비행 소모 등 관련 타이머를 함께 다루는 별도 규칙이 필요하다.

### 3.4 구멍 코스

- 원안: 여러 구멍이 있는 길, 구멍 무늬의 대왕과 좌우 화살표.
- 제안 코스: 짧은 고정 구멍 → 점프 간격이 다른 구멍 → 열리기 전에 표시되는 임시 구멍 → 보스방.
- 고정 구멍은 기존 낭떠러지와 타일맵으로 구성한다. 임시 구멍은 정해진 발판의 충돌을 껐다 켜는 방식으로 제한한다.
- 구멍 그림만 표시하고 실제 바닥은 남는 불일치를 방지한다. 원형 무늬는 시각 표현으로 사용하되 추락 판정은 실제 충돌 지형과 일치시킨다.
- 보스 패턴 제안: ① 좌우로 이동하며 한 곳의 구멍 예고 ② 두 위치를 번갈아 열기 ③ 이동과 순차 개방 조합. 공격 후 중앙의 안전한 발판에서 약점이 열린다.
- 예고 없이 플레이어 발밑을 열지 않는다. 모든 안전 발판이 동시에 없어지는 조합을 금지하고 체크포인트는 고정 바닥에 둔다.
- 구멍을 통한 순간이동은 원안에서 확인되지 않았으므로 1차 범위에 포함하지 않는다.

### 3.5 구름 코스

- 사용자 확정: 구름 대왕을 위한 새 코스를 추가한다. 코스 이름·구조·공격은 제안이다.
- 구름 대왕의 울퉁불퉁한 몸, 긴 팔다리, 뾰족한 입 모양을 외형 기준으로 삼는다.
- 제안 코스: 안전한 구름 다리 → 움직이는 구름 → 상승기류와 짧은 비행 → 구름 성 보스방.
- 구름 발판·상승기류·변신을 우선 재사용한다. 비행 게이지가 부족하면 착지해 회복하거나 보조 발판으로 진행할 수 있게 한다.
- 보스 패턴 제안: ① 한 방향 돌풍 ② 예고 지점의 빗방울 낙하 ③ 두 공격을 순차 조합. 공격 뒤 낮은 구름 발판으로 내려와 머리 약점을 연다.
- 보스를 밟는 데 제한된 비행 시간이나 특정 변신이 필수가 되지 않도록 기본 점프와 발판으로 접근 가능하게 한다.

## 4. 공통 보스 규칙과 난이도

- 기본 HP는 3, 유효 타격마다 한 단계씩 패턴이 바뀐다. 속도만 올리는 방식보다 공격의 조합과 순서로 차이를 만든다.
- 공통 흐름은 **등장 → 예고 → 공격 → 약점 노출 → 회복 → 다음 공격 / 처치**다. 각 보스의 세부 상태는 전용 행동 모듈에 둔다.
- 초기 조정 범위 제안: 공격 예고 0.9~1.2초, 약점 1.8~2.2초. 쉬운 모드는 예고·약점 시간을 늘리고 동시 위험 수를 줄인다.
- 어떤 타격이 유효했는지 외형·소리·보스 HP로 함께 알린다. 무음과 효과 감소 상태에서도 규칙을 이해할 수 있어야 한다.
- 공격마다 날개 방어 가능 여부를 명시한다. 혀나 바닥 구멍까지 투사체와 동일하게 처리하지 않는다.
- 보스 직전에 HP·비행을 회복할 체크포인트를 둔다. 부활 직후 재공격에 맞지 않도록 예고와 안전 시간을 보장한다.
- 보스 처치 후 투사체·끈끈이·정지 상태·임시 구멍을 정리하고 게이트로 가는 바닥을 복구한다.
- 필수 목표는 해당 보스의 `defeat_boss`와 `reach_gate`다. 별·시간·비밀 공간은 선택 목표로 유지한다.
- 신규 코스의 초기 목표 플레이 시간은 보스 포함 4~6분으로 제안한다. 5초 대기 누적이 피아노 코스 체류 시간을 과하게 늘리지 않는지 별도로 본다.

- `src/data/levels/index.js`의 LEVELS, import, 개발용 데이터 재로드 목록을 함께 갱신한다.
- 신규 해금, 다음 스테이지 이동, 11번 이후 마지막 레벨 처리와 기존 저장 데이터 호환성을 검증한다.
- `StageSelectScene`에 새 미리보기를 연결하고 11개 카드 탐색·잠금·키보드·게임패드 입력을 확인한다.

### 보스

- `bossDefinitions.js`, `bossPatterns.js`, `bossBehaviorTypes.js`, `systems/bosses/index.js`에 다섯 보스를 등록한다.
- `MerongKingBehavior.js`, `TapeKingBehavior.js`, `MusicKingBehavior.js`, `HoleKingBehavior.js`, `CloudKingBehavior.js`를 추가한다.
- 기존 `BossController`의 유효 타격·이벤트 계약과 `LevelLoader`의 보스 생성·게이트 흐름을 재사용한다.
- 보스 체형에 맞는 충돌 박스와 머리 약점 도달성을 검증한다. 애니메이션이 바뀌어도 판정이 불필요하게 흔들리지 않게 한다.

### 환경 장치

- 끈끈한 바닥은 `terrainMechanics.stickyZones` 형태를 후보로 삼는다. `TerrainMechanicsManager`에서 접촉을 판정하고 기존 이동 보정과 합성한다. 기본 tuning 값을 직접 덮어쓰지 않는다.
- 피아노 규칙은 독립된 `RhythmMechanicsManager`와 순수 판정 데이터 모듈을 후보로 삼는다. 레벨 데이터로 신호·대기 시간·안전 영역을 지정한다.
- 임시 구멍은 `terrainMechanics.timedHoles` 형태를 후보로 삼아 지형 충돌의 개방·복구를 관리한다. 기존 붕괴 발판과 공유할 수 있는 부분만 재사용한다.
- 이 필드들은 **현재 존재하는 API가 아니라 추가 설계 후보**다. 스키마·범위 검증·쉬운 모드 변환·재로드를 함께 지원한다.
- `GameScene`은 공통 시스템을 연결하는 역할만 맡고 특정 레벨명이나 배치 좌표를 분기하지 않는다.
- 환경/보스의 정지·재개는 기존 시스템 정지 계약을 확장한다. 일시정지, 부활, 보스 처치, 레벨 재시작, 데이터 재로드, Scene 종료 시 상태와 타이머를 정리한다.
- 불필요한 범용 보스 엔진 재작성은 피하고, 다섯 보스에서 실제 반복되는 예고·위험 표시·자원 정리만 작은 공통 기능으로 추출한다.

### 이미지·오디오

- 원안의 실루엣을 살린 보스 기준 이미지 → 필요한 동작 프레임 → 실제 화면 크기·충돌 판정 순으로 제작한다.
- 스테이지마다 배경, 타일·장치, 선택 화면 미리보기, 보스, 전용 공격 효과를 준비한다.
- 보스 동작은 대기·예고·공격·약점·피격·처치를 기본으로 하되 기존 점프/낙하 등 사용하는 애니메이션 역할 계약도 충족한다.
- 피아노의 시작·정지·해제 효과음은 서로 구분되게 하고 BGM과 혼동되지 않게 한다. 기존 오디오 생성·등록 흐름을 활용한다.
- `assets/manifest.json`, `references/mapping.json`, `enemyAnimations.js`, `ASSET_LIST.md`를 함께 갱신한다. 변형 체형이 필요한 보스는 기존 프레임 규격에 억지로 맞추기 전에 별도 규격을 명시한다.
- 최종 에셋이 없어도 도형 fallback으로 규칙과 클리어 경로를 먼저 확인할 수 있게 한다.

## 6. 개발 순서와 단계별 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| N0 — 원안 정리 | 5개 코스 구성, 피아노 정지 의미, 영상 음성의 추가 규칙 확인 | 확정 요구와 제안을 구분한 코스·보스 명세 |
| N1 — 기술 검증 | 개발 전용 짧은 코스에서 감속·5초 정지·임시 구멍을 도형으로 시험 | 기존 이동·변신·일시정지와 함께 동작하고 부활 시 정상 복구 |
| N2 — 메롱 왕국 완성 | 신규 보스 등록과 궁전 진입, 3단계 전투, 게이트·저장 연결 | 선택 → 코스 → 보스 처치 → 게이트 → 결과 → 다음 해금까지 완주 |
| N3 — 테이프 도시 | 끈끈한 지형과 테이프 대왕 | 감속 해제 누락 없이 양 난이도에서 완주 |
| N4 — 피아노 나라 | 신호·정지 규칙과 음악 대왕 | 무음·게임패드·공중 진입·일시정지에서도 공정한 판정 |
| N5 — 구멍 코스 | 고정/임시 구멍과 구멍 대왕 | 표시와 충돌 일치, 안전 경로 보장, 처치 후 바닥 복구 |
| N6 — 구름 코스 | 구름 발판과 구름 대왕 | 기본 점프 도달성, 비행 회복 경로, 최종 레벨 마무리 |
| N7 — 통합 조정 | 아트·사운드·선택 화면·문서·전체 회귀 검사 | 11개 스테이지 진행 및 기존 기록 호환, 릴리스 검사 통과 |

N2~N6은 각각 **임시 도형으로 완주 → 이미지·애니메이션 적용 → 실제 화면·난이도 검수**를 거친다. 다섯 스테이지의 이미지를 먼저 전부 만드는 대신, 첫 완성 스테이지에서 적정 길이와 보스 접근 방식을 확인한 후 확장한다.

## 7. 검증 계획

### 새 규칙에 필요한 자동 검사

- 끈끈한 영역 진입·중복·이탈 시 속도 보정, 부활·재로드 후 보정 해제.
- 피아노 신호 순서, 정확한 5초 판정, 미세 이동 허용, 일시정지 후 시간 보존, 실패 중복 피해 방지.
- 임시 구멍 예고·개방·복구, 충돌과 표시 일치, 모든 안전 발판의 동시 소멸 금지.
- 각 보스의 3단계 전이, 약점 외 타격 거부, 한 번에 HP가 여러 번 줄지 않음, 처치·종료 후 타이머/투사체 정리.
- 7~11번 레지스트리·진행 연결, 6→7 해금, 기존 저장 불러오기, 11번 클리어 후 다음 레벨 없음.
- 레벨 데이터의 안전한 체크포인트·약점 도달성·자산 키·쉬운 모드 차분 검증.

구현 변경 범위에 맞춰 기존 `npm test`, `npm run validate`와 신규 규칙 검사를 실행한다. 최종 릴리스는 저장소 기준의 `npm run spritesheets`, `npm test`, `npm run validate`, `npm run test:soak`, `npm run test:release`를 따른다. 문서 작성만 하는 이번 단계에서는 이 실행 결과를 완료했다고 기록하지 않는다.

### 실제 플레이 검사

- 기존 모든 선택 가능 캐릭터, 일반/쉬운 모드에서 신규 스테이지를 완주한다.
- 키보드·게임패드, 무음·효과 감소, fallback 표시를 확인한다.
- 변신 없이 진입, 비행 게이지 소진, 보스 직전 추락, 정지 중 일시정지, 보스 중 재시작을 재현한다.
- `PlaytestManager`의 레벨·보스 key/phase 기록을 활용한다. 새 장치 실패 사유가 필요하면 정지 위반·끈끈이 체류·임시 구멍 추락을 추가 기록한다.
- 자동 검사와 실제 어린이 플레이테스트를 구분한다. 사람이 수행하지 않은 난이도·재미 검증을 완료로 간주하지 않는다.

## 8. 착수 전에 남은 결정

1. 피아노의 5초 정지 의미. 현재 추천안은 자발적 정지다.
2. 영상 음성에 사진에 없는 공격 방식·보상·규칙이 있는지. 해당 내용은 전사 또는 별도 설명을 확보한 뒤 명세에 반영한다.
3. 제안한 코스 순서와 보스 패턴의 최종 선택. 특히 구멍의 개폐와 구름의 돌풍은 개발 제안이다.

N1에서 개발용 장치 시험을 완료했다. 다음 N2의 구현 범위는 **메롱 왕국 한 스테이지의 완주 흐름**이다. 이를 기준으로 다음 네 스테이지의 제작·검수 방식을 반복한다.
